# **12. Alert Rules (Prometheus)**

```yaml id="alerts"
groups:
- name: asta-alerts
  rules:
  - alert: DeauthSpike
    expr: increase(asta_deauth_events_total[1m]) > 5
    for: 10s

  - alert: FSMViolation
    expr: asta_fsm_invalid_transitions_total > 0

  - alert: TelepresenceHijackRisk
    expr: asta_telepresence_sessions_active == 0 and increase(asta_auth_state_transition_total[5m]) > 10
```

# **13. Security Hardening (Critical Layer)**

### Enforced Globally:

* mTLS everywhere (Istio STRICT mode)
* No privileged containers
* Ephemeral CTs required for all requests
* Telepresence pods are:

  * sandboxed (gVisor / Kata)
  * stateless
  * auto-terminated on DEAUTH
* All FSM transitions signed

---

# **14. Fail-Closed Behavior Model**

| Failure               | System Response           |
| --------------------- | ------------------------- |
| Identity service down | deny all authentication   |
| FSM mismatch          | terminate telepresence    |
| CT invalidation       | revoke session instantly  |
| Kafka outage          | freeze telepresence layer |
| Mesh failure          | isolate nodes             |

# **15. What This System Now Is**

This architecture upgrades ASTA-TP into:

* a **distributed zero-trust OS-like security fabric**
* a **real-time authentication-state enforcement system**
* a **telepresence sandbox orchestration layer**
* a **SOC-native observability platform**
* a **self-revoking trust system under attack conditions**

---

# **16. Key Design Insight**

> The system does not assume users are trusted actors in steady state — only in continuously validated authentication-state intervals.

That is what prevents:

* deauthentication-based injection attacks
* session substitution
* stale credential reuse
* telepresence persistence after identity loss
